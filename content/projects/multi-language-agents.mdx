<Block colSpan={6} rowSpan={1} variant="text">
  <h2>End-user personalization</h2>
  <p>The agent should speak the customer's language from the first message — not after a click. We used the browser's default language signal to set the conversation language automatically, so users on the end-user side never had to pick from a menu before they could ask their question.</p>
</Block>

</Block>

<SectionBreak />

<Block colSpan={6} rowSpan={1} variant="text">
  <h2>Admin setup</h2>
  <p>On the admin side, the setup flow lets admins choose which languages and locales the agent supports. The decision is explicit and scoped — admins control the surface area, and the agent only responds in languages they've signed off on.</p>
</Block>

<Block colSpan={6} rowSpan={4} variant="media" aspectRatio={1.6}>
  <Media src="/images/projects/multi-language-agents/admin-setup.png" alt="Admin configuring available languages and locales" />
</Block>

<SectionBreak />

<Block colSpan={6} rowSpan={1} variant="text">
  <h2>Preview before deploy</h2>
  <p>Admins can test the conversation in each configured language inside the Agent Builder preview before going live. This closes the trust gap — admins see the agent's actual behavior in every language they've enabled, so they can deploy with confidence.</p>
</Block>
